# Deploying the prototype on Render

The choices behind this guide are in [`specs/api.md`](../specs/api.md), section 6.

## What gets deployed

One web service, built from the `Dockerfile` at the root of the repository:

- **Stage 1**: Node builds the clinician interface (`frontend/dist`).
- **Stage 2**: Python 3.12 runs the API with uv. The API also serves the interface, so the jury opens a single address.

`render.yaml` declares the service:

| Setting | Value | Why |
|---|---|---|
| Region | `frankfurt` | closest to Abu Dhabi among the five Render regions |
| Plan | `0.5c-512mb` (7 $ a month) | the API used 220 MB in a local measurement (after loading the personas, and at the peak of a live session); `1c-2g` (25 $ a month) if it runs short |
| Health check | `/health` | Render waits for it before switching traffic |
| Disk | 1 GB on `/var/data` (0.25 $ a month) | keeps the sessions recorded during the evaluation |
| Database | `CHRONOVOICE_DB=/var/data/chronovoice.sqlite3` | on the disk |
| Model | `LLM_PROVIDER=mistral`, `MISTRAL_MODEL=mistral-medium-latest` | the model chosen on 2026-11-14 |

Prices are those of the Render pricing page on 2026-11-14.

## Steps

These steps need your Render account; they are yours to do.

1. **Create a Render account** and connect it to GitHub, with access to the `chronovoice-brain-health` repository.
2. In the Render Dashboard, choose **New → Blueprint**, then select the repository. Render reads `render.yaml`.
3. **Enter the two secrets** when Render asks for them:
   - `MISTRAL_API_KEY`;
   - `ELEVENLABS_API_KEY`.

   Render only asks for them when the Blueprint is first created. `INTEGRATION_API_KEY` is generated by Render; you can read it later in the service's Environment page.
4. **Apply the Blueprint.** The first build takes several minutes: it downloads the language model of spaCy and builds the interface.
5. **First start.** The database is empty, so the API loads the three personas before it answers. This takes a few seconds.
6. **Check**:
   - `https://<service>.onrender.com/health` answers `{"status": "ok", "phase": "prototype"}`;
   - the home page lists Margaret, Grace and Rajesh;
   - recording a short session with the microphone works (the address is HTTPS, as the browser requires).

## Running the service

- **New code**: every push to `main` redeploys the service. With a disk, the service is down for a few seconds during the switch.
- **Back to the demo state**: open the service's **Shell** page in Render and run:

  ```bash
  python -m scripts.reset_demo
  ```

  The personas come back and every recorded session is removed.
- **Logs**: the service's Logs page shows each request, and one plain line when a step fails (for example `transcription of s-… failed: …`, once per attempt). A session that goes well writes nothing beyond its requests.
- **Daily snapshots**: Render snapshots the disk every day and keeps each snapshot for 7 days.

## What was checked before the first deploy

On the development machine (an Apple Silicon Mac, Docker Desktop):

- **2026-11-14, without Docker**: the install of the image (`uv sync --locked --no-dev`) and its start command work; without keys, a recording is refused with a clear message (503). Memory: 220 MB.
- **2026-11-15, full `docker build`**, for the machine's architecture (arm64) and for Render's (`--platform linux/amd64`, under emulation): both build.
- **2026-11-15, the container run as on Render**: the keys from `backend/.env`, `CHRONOVOICE_DB=/var/data/chronovoice.sqlite3` on a Docker volume, port 10000.
  - On a fresh volume, the three personas load before the API answers; `/health`, the pages and the API answer, and the interface is served.
  - A real 71-second recording (speech synthesis, two voices) is transcribed by Scribe, measured, and analysed by Mistral Medium in about 2 seconds; the session is "partial" (under 2 minutes) and the orientation stays "building baseline 0/3". The audio file is deleted after processing.
  - A corrupted audio file ends as "failed", with Scribe's message, after two attempts; each attempt writes one line in the logs.
  - Memory: about 195 MB for the arm64 image, 215 MB for the amd64 image under emulation.
- **Not checked**: the build on Render itself, and recording with the microphone over HTTPS.

## Things to know

- **Guest access**: anyone with the address can record a session, which uses ElevenLabs and Mistral credits. Share the address with the jury only.
- **Deprecated model**: Mistral Medium 3.5 has been deprecated since 2026-10-31. If Mistral retires it, sessions keep working (no narrative analysis, fixed-wording summaries); remove `MISTRAL_MODEL` in the Environment page to fall back to Mistral Small 4.
- **Secrets**: never in the repository. `.dockerignore` keeps `.env` files and local databases out of the image.
